01

LET：给公式起名字

它是后面所有长公式的地基——没有它，一条流水线会难读十倍。

语法是一个"名字、值、名字、值、…、最后结果"的配对列表：

fx=LET(名字1, 值1, 名字2, 值2, …, 最终计算)

配对必须是偶数个参数，最后多出来的那一个才是返回值。上面这行里的 名字N 一旦定义，后面的表达式就能直接引用它，不必重复写同一段区域引用或同一个计算。

对照：不用 LET 会怎样

fx' 同一段 IFERROR(--A2:A11, A2:A11) 写了三遍 =IFERROR(--A2:A11,A2:A11)&"|"&SUM(IFERROR(--A2:A11,A2:A11))
fx' 用 LET 之后，只写一遍 =LET(arr, IFERROR(--A2:A11, A2:A11), arr&"|"&SUM(arr))

好处有三层：可读（一眼看出 arr 是什么）、好改（改一处即可）、更快（同一段计算只算一次，而不是每出现一次就算一遍）。

约定

本教程统一用这几个名字，看到它们就能对上号：

  • rng — 原始区域
  • arr — 类型处理后的数组
  • cond — 布尔条件数组
  • same — 相邻是否相等
  • chg — 是否开启新分组
  • group — 分组编号
02

减负运算：-- 与 IFERROR

把"长得像数字的文本"变成真数字。

-- 是两个减号，术语叫减负运算（double unary）。它的作用是强制类型转换：对文本数字做两次取负，值不变，但类型从"文本"变成了"数字"。

fx=--"123" → 123 （文本转数字） =--100 → 100 （本来就是数字，不变） =--"abc" → #VALUE! （转不了，直接报错） =--TRUE → 1 （逻辑值转数字）

单独用它会很脆——只要区域内有一个转不了的值，整个公式就崩。所以永远和 IFERROR 配对：能转就转，转不了就原样保留。

fxarr, IFERROR(--rng, rng)

坑 1 · 空白会变成 0

-- 遇到真正空白的单元格返回 0，不报错，所以 IFERROR 兜不住它。如果后面又用"不等于 0"来筛，这些空白行会被顺手剔掉——多数时候是想要的效果，但要清楚这是"被当成 0"而不是"被当成空"。

坑 2 · 空格不算空

一个只敲了空格的单元格，-- 转不了（报 #VALUE!），IFERROR 会把它原样留下。它看起来是空的，但所有"非空判断"都会认为它有内容。要彻底干净，外面再套一层 TRIM。

03

比较运算的类型顺序

本节是全文最关键的一节，也是你原来那条公式报 #CALC! 的真正原因。

Excel 用 > < 比较大小时，不同类型之间不是按数值大小比，而是按一套固定的类型优先级：

优先级 高

逻辑值

TRUE / FALSE

优先级 中

文本

含空文本 "" 和空格 " "

优先级 低

数字

所有数值、日期

也就是说，任何文本都比任何数字大——连同空文本 "" 在内。于是：

fx=100>"" → FALSE （数字 < 文本，即使文本是空的） =-2>"" → FALSE （负数也一样） =0>"" → FALSE =100<>"" → TRUE （这才是正确的"非空"判断） ="abc">"" → TRUE （非空文本大于空文本） =（空白）<>"" → FALSE （真正空白的单元格，等于空文本）
结论 · 这就是 #CALC! 的根因

用 (rng > "") 当"非空"条件时，整列数字全部返回 FALSE，条件数组全为 0，FILTER 一个都没匹配上 → 直接抛 #CALC!。

正确的写法只有一个：(rng <> "")。

三种"看起来像非空判断"的写法对比

写法数字非空文本空白适用
rng > ""FALSETRUEFALSE只适合纯文本列，数字列必崩
rng <> ""TRUETRUEFALSE通用，推荐
ISNUMBER(rng)TRUEFALSEFALSE只保留数字，剔除全部文本

表 3-1 · 非空判断的三种写法（空白指真正没填过的单元格）

顺带一提

这套"文本 > 数字"的规则只作用于逻辑运算符（> < = >= <=）。COUNTIF / SUMIF 这类统计函数另有一套规则：条件与区域类型不一致时直接忽略，不参与比较。所以 COUNTIF 和 SUMPRODUCT(--(区域>值)) 经常会算出不一样的结果，这是正常的。

04

FILTER：按条件筛选

条件数组是布尔值，它只负责"哪几行通过"。

fx=FILTER(要返回的数组, 条件数组, [一个都没匹配时返回什么])

第三个参数 if_empty 是可选的，但强烈建议每次都写——原因见下面。

条件数组怎么来

条件数组必须和返回数组行数完全一致，元素是 TRUE / FALSE。多个条件用乘法相连（乘号等价于 AND，加号等价于 OR）：

fxcond, (arr<>"") * (arr<>0) ' arr<>"" → 非空 ' arr<>0 → 不等于 0 ' 相乘 → 两个条件同时满足才通过
#CALC! 的头号来源

省略第三个参数时，只要条件数组里没有任何一个 TRUE，FILTER 会返回一个空数组，Excel 立刻报 #CALC!。空数组不是合法的溢出结果。

加上 ""（或任意兜底值）之后，没匹配到就安静地返回空，公式不炸。

fx=FILTER(arr, cond, "") ' 一个都没匹配 → 返回空，不报错

为什么 IFERROR 兜不住 FILTER 的空数组

因为空数组不是错误，IFERROR 接不住它。空数组是 FILTER 的一个合法返回值，只是下游容不下它（溢出到工作表时没有可写的行），才抛出 #CALC!。所以兜底必须写在 FILTER 自己的第三个参数上。

和传统写法的对照

老版本里要写 IFERROR(INDEX(...,SMALL(IF(...))),"") 并按 Ctrl+Shift+Enter 输入。FILTER 把"条件 + 提取 + 容错"三件事压成一行，而且结果是真正动态的——源数据一改，结果自动伸缩。

05

SORTBY：多关键字排序

注意，它和 SORT 不是一回事。

fx=SORTBY(要返回的数组, 排序依据1, [升序1], 排序依据2, [升序2], …)
  • 1 = 升序，-1 = 降序，省略时默认升序。
  • 排序依据可以有很多组，靠前的优先级更高。前面一样的，才轮到后面比。
  • 排序依据数组和返回数组行数必须一致。

SORT 和 SORTBY 的区别

SORTSORTBY
排序对象数组自己的某一列（用列序号指定）数组本身不动，另拿一组数组当标尺
多关键字只能按数组内部的列可以按外部任意数组，包括计算结果
典型用途整表按第 2 列排序行号 / 序号跟着业务字段一起排

拆解一段真实写法

fx=SORTBY(idx, r, 1, t, 1, idx, 1)
位置值含义
返回数组idx最终要输出的东西，通常是行号 / 序号数组
依据 1r, 1第一优先级：按 r 升序
依据 2t, 1第二优先级：r 相同时，按 t 升序

最后那个 idx 是干什么的

它是稳定排序的兜底。前两组依据都打平时，用原始序号再排一次，保证"值相同的行"始终维持原来的先后顺序，结果不会因为引擎实现不同而乱跳。

坑 · 排序后行号就失效了

如果把 FILTER 筛出来的行号交给 SORTBY 排序，排完之后的行号仍然指向原表位置，而不是"新顺序的第 N 行"。后续再拿这个数组去和别的数组按位置相乘 / 比对，必须先想清楚对齐关系，否则结果会整体错位。

DROP：制造"错位一行"的两个数组

让数组自己和自己错开对比，是识别"连续段"的第一步。

fx=DROP(数组, n) ' n 为正：砍掉开头 n 行 ' n 为负：砍掉结尾 |n| 行

拿一个 6 行的数组 arr = {10;10;20;20;20;30} 来看：

表达式结果
arr{10; 10; 20; 20; 20; 30}
DROP(arr, 1){10; 20; 20; 20; 30}　去掉第 1 行
DROP(arr, -1){10; 10; 20; 20; 20}　去掉最后 1 行

把这两个错位数组逐行比较，就得到了每一行与它下一行是否相同：

fxsame, --(DROP(arr, 1) = DROP(arr, -1))

别漏了前面那两个减号——= 的比较结果是 TRUE / FALSE，-- 把它们变成 1 / 0，后面做加法时才不需要额外转换。得到：

fxsame = {1; 0; 1; 1; 0} ' 1 = 与下一行相同，0 = 与下一行不同
坑 · same 比原数组少一行

6 行数据两两对比只有 5 个结果。这个"短一行"如果不管，后面和 6 行的数组放在一起运算或拼接，尺寸不匹配直接抛错。解决办法见下一节。

07

VSTACK：把行数补齐

一个 VSTACK(1, …)，把"少一行"的数组救回来。

fx=VSTACK(数组1, 数组2, …) ' 按列对齐，上下摞起来

它最常见的用法不是拼接两份数据，而是在数组顶部硬塞一个值，把行数补回全长。因为第 1 行前面没有"上一行"，它必然是分组的起点：

fxchg, VSTACK(1, 1 - same)
行same1 − samechg（补顶后）
1——1　← 手动补的
2100
3011
4100
5100

表 7-1 · chg 的构造过程（same 与 1−same 已向下错开一行对齐到各自作用的行）

要理解 1 - same，先记住 same 的含义：和下一行相同就是 1。那"不一样"自然就是 1 - same：

  • same = 1 → 与下一行相同，没换组 → 1-same = 0
  • same = 0 → 与下一行不同，新组开始 → 1-same = 1

于是 chg 变成一张"断点表"：1 表示"从这里开一个新组"，0 表示"继续待在当前组"。

fxchg = {1; 0; 1; 0; 0; 1} ' 6 个元素，与 arr 长度一致
为什么用"错位 + 取反"而不是硬判断

这个写法对数字、文本、日期一视同仁，不需要为不同数据类型写不同分支。这也是 Islands & Gaps 能成为通用套路的原因。

08

SCAN：把断点累加成编号

遇到 1 就 +1，遇到 0 就保持不变——分组编号就出来了。

fx=SCAN(初始值, 数组, LAMBDA(累计值, 当前值, 计算式))

SCAN 遍历数组，把上一轮的结果作为"累计值"传进下一轮，并输出每一步的累计值（输出长度与输入相同）。要的累计方式是加法：

fxgroup, SCAN(0, chg, LAMBDA(acc, val, acc + val))
行chg累计值 acc + val含义
110 + 1 = 1第 1 行，开第 1 组
201 + 0 = 1没断点，留在第 1 组
311 + 1 = 2断点，开第 2 组
402 + 0 = 2留在第 2 组
502 + 0 = 2留在第 2 组
612 + 1 = 3断点，开第 3 组

表 8-1 · SCAN 逐步累加

fxgroup = {1; 1; 2; 2; 2; 3}

到这里编号已经生成。最后用 HSTACK 把它和原值并排输出即可：

fx=HSTACK(arr, group)
LAMBDA 的写法要点

LAMBDA(acc, val, acc + val) 里前两个是参数名（随便起，本教程用 acc / val），最后一个是用到这两个参数的计算式。这些名字只在本次 LAMBDA 内部有效，不会污染外面的 LET 变量。

分组推演：五步走完 Islands & Gaps

点"下一步"，看同一列数据一步步变成分组编号。这就是前面所有零件拼起来的样子。

arr = {10; 10; 20; 20; 20; 30}
arr原始值 same与我下一行相同？ 1 − same与下一行不同？ chg从这里开新组？ group分组编号
1 10 1 0 1 1
2 10 0 1 0 1
3 20 1 0 1 2
4 20 1 0 0 2
5 20 0 1 0 2
6 30 — — 1 3

步骤 0 / 4原始数组。6 个值，先看看它自己——接下来要用 DROP 把同一列错开成"我的下一行"和"我的上一行"两组。

same 列为什么只有 5 个值

它回答的是"第 i 行与第 i+1 行是否相同"，所以第 6 行后面没有可比的下一行，用"—"占位。真实参与运算时，这一列只有 5 个元素，这正是下一步要用 VSTACK 补行的原因。

完整公式

fx=LET( arr, A2:A7, same, --(DROP(arr,1) = DROP(arr,-1)), chg, VSTACK(1, 1-same), group, SCAN(0, chg, LAMBDA(acc, val, acc+val)), HSTACK(arr, group) )

四个中间变量，一行一个职责：arr 拿数据，same 找相邻关系，chg 标断点，group 编组号。整条公式没有一处重复计算，改数据源只需要动 A2:A7。

结果

两列输出：左列是排好序的值，右列是它所属的连续段编号（1 / 2 / 3）。整条公式只引用了一次源区域，其余全部是变量之间的引用。

注意 SORTBY 的第二个参数

这里 SORTBY(r, r, 1) 的"返回数组"和"排序依据"是同一个 r，所以它等价于对 r 自身升序排序。如果排序依据换成别的数组（比如按另一列的业务字段排序），返回的仍然是 r 的顺序，两者必须行数一致。

报错速查

看到错误码，直接对号入座。

错误在这个函数族里的常见原因怎么修
#CALC! FILTER 一个都没匹配、又没写第三个参数；或 HSTACK / 运算两侧数组行数不一致（典型：same 少一行没补）；或把空数组喂给了要求非空的函数。 补 FILTER 第三参数；给 same 套 VSTACK 补行。
#VALUE! -- 撞上了无法转成数字的文本；或 SORTBY / FILTER 的数组与依据行数不匹配。 用 IFERROR(--rng, rng) 包住；核对两侧行数。
#SPILL! 结果要溢出的区域里，已经有别的单元格在占位。 清空结果区域，或把公式挪到一个空列。
#NAME? 当前版本不认识 LET / FILTER / SCAN 这些函数。 换 Excel 365 / WPS 新版；老版本改用传统数组公式。
#N/A 这个函数族本身很少产生 #N/A，多半是上游的查找函数（VLOOKUP / XLOOKUP / MATCH）漏出来的。 顺着依赖往上游查，不要在这里改。
